# ブログ記事の追加方法

このディレクトリ（`content/blog/`）に Markdown ファイルを1つ追加するだけで、
`/blog/` の一覧と `/blog/<ファイル名>/` の記事ページに自動的に反映されます。
React コンポーネントを編集する必要はありません。

## 1. ファイルを追加する

`content/blog/<slug>.md` という名前で作成してください。
**ファイル名（拡張子を除いた部分）がそのまま記事のURL（slug）になります。**
例: `content/blog/aircon-cleaning-necessity.md` → `/blog/aircon-cleaning-necessity/`

- 半角英数字とハイフンのみを使用してください（日本語ファイル名は不可）
- 一度公開した記事のファイル名は、SEO評価が引き継がれないため基本的に変更しないでください

## 2. frontmatter（記事の先頭）

```md
---
title: "記事タイトル（32文字前後を目安に）"
description: "検索結果に表示される説明文（100〜160文字程度）"
publishedAt: "2026-08-12"
updatedAt: "2026-08-12"
category: "エアコンクリーニング"
author: "東京おうちミガキ。編集部"
thumbnail: "/images/blog/xxxxx.jpg"
---
```

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| `title` | ✅ | 記事タイトル。`<title>`・OGP・構造化データに使われます |
| `description` | ✅ | meta description・OGP descriptionに使われます |
| `publishedAt` | ✅ | 公開日（`YYYY-MM-DD`） |
| `updatedAt` | – | 更新日。省略時は `publishedAt` と同じ扱いになります |
| `category` | ✅ | 下記「カテゴリ一覧」のいずれか1つ |
| `author` | – | 省略時は「東京おうちミガキ。編集部」になります |
| `thumbnail` | – | `public/images/blog/` 配下の画像パス。**省略可**。省略した場合はカテゴリに応じたブランドプレースホルダー画像が自動表示されます（画像を無理に用意する必要はありません） |

`slug` はフロントマターに書きません。ファイル名がそのままslugになります。

### カテゴリ一覧（`src/types/blog.ts` の `BLOG_CATEGORIES`）

- エアコンクリーニング
- 水回りクリーニング
- お掃除の知識
- 施工事例
- 地域情報

新しいカテゴリが必要な場合は `src/types/blog.ts` の `BLOG_CATEGORIES` と
`src/data/blogCategories.ts` のアイコン対応を追加してください（既存記事には影響しません）。

## 3. 本文（Markdown）

- `#`（H1）は使わないでください。タイトルはページ側が自動で見出しとして表示します。本文は `##`（H2）から始めてください
- 表・箇条書き・強調（GFM）が使えます
- LP内の該当箇所へ自然にリンクしたい場合は、通常のMarkdownリンクを使ってください
  - 例: `[エアコンクリーニングの料金表](/#pricing)`
  - 主なリンク先: `/#pricing`（料金）, `/#other-services`（浴室・レンジフード・トイレ）,
    `/#before-after`（施工事例）, `/#contact`（対応エリア・LINE相談）
  - リンクは文章に自然に溶け込む範囲にとどめ、SEO目的で無理に増やさないでください
- 本文中の好きな位置に `<!-- CTA -->` という行を1つだけ置くと、そこにLINE無料見積もりの
  CTAブロックが自動で挿入されます（記事下部には常にCTAが表示されるため、必須ではありません）

## 4. 運用ルール（重要）

- **AI生成 → 人間による内容確認 → 公開** を必ず徹底してください。このリポジトリの仕組み自体は
  記事を自動で本番公開しません（`git push` するまで公開されません）が、生成した内容を
  レビューせずコミットしないようにしてください
- 料金・サービス内容・対応エリア・作業内容など、事実に関わる情報は
  `src/data/pricing.ts` / `src/data/services.ts` / `src/data/siteConfig.ts` に
  実際にある情報のみを使用してください。存在しない金額や対応内容を作成しないでください
- 医療・健康上の効果を断定する表現（「アレルギーが治る」等）は使用しないでください
- 施工事例記事は、実際に提供された「施工地域・清掃箇所・Before/After写真・汚れの状態・作業内容」
  のみを使用して作成してください。存在しない施工内容や顧客情報を創作しないでください
- 地域名だけを入れ替えたほぼ同一内容の記事を量産しないでください。地域記事を作る場合は、
  その地域固有の情報（現地の施工事例、アクセス、地域特有の悩みなど）を含め、
  読者にとって独自の価値がある内容にしてください
- FAQ形式の内容を含める場合でも、`FAQPage` 構造化データの追加は慎重に判断してください。
  Googleの現在のガイドラン上、FAQPageのリッチリザルト表示は一部のサイトに限定されており、
  追加したからといって検索結果での表示が保証されるものではありません

## 5. 動作確認

```bash
npm run dev
```

`http://localhost:3000/blog/` で一覧に表示されること、
`http://localhost:3000/blog/<slug>/` で記事が正しく表示されることを確認してください。
公開前に必ず `npm run build` でエラーがないことも確認してください。
